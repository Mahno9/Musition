# ТЗ: локальное приложение для работы с sound-gen моделями

## 1. Цель

Единый интерфейс (браузер, localhost) для запуска генерации на всех локально развёрнутых
моделях из `c:\Projects\AI\Musition` — без ручного вызова `run.py`/`infer.py` из консоли,
с полным контролем параметров и историей результатов.

## 2. Область применения

**В скоупе — 4 локальные модели**, каждая своей вкладкой:
- AudioGen (SFX по тексту)
- Stable Audio Open (SFX / короткая музыка до ~47с)
- Bark (TTS + невербальные звуки)
- ACE-Step (музыка до 4 мин, вокал+инструментал)

**Плюс 2 вкладки-ссылки** (не встроенная генерация, просто переход на хостинг):
- HunyuanVideo-Foley → https://huggingface.co/spaces/tencent/HunyuanVideo-Foley
- YuE → карточка с пояснением, почему не локально (нужно 24-80GB VRAM), и ссылками на
  официальный репозиторий и low-VRAM форк YuEGP

**Плюс вкладка «Галерея»** — история всех генераций.

## 3. Архитектура

Ключевое ограничение, подтверждённое замерами при установке: **все 4 модели живут в разных
`.venv` с несовместимыми версиями torch/transformers**, и **VRAM (12GB) не хватает, чтобы
держать больше одной модели загруженной одновременно** (ACE-Step сам по себе занял 7.4GB,
Bark в полной версии документирован до 12GB). Из этого следует архитектура:

```
Браузер (localhost:8000)
   │
   ▼
Оркестратор (1 лёгкий процесс, FastAPI, свой минимальный venv)
   │  раздаёт фронтенд (статический HTML/CSS/JS, без React/Vue — не нужен)
   │  проксирует запросы генерации к воркерам
   │  следит, что активен только ОДИН воркер модели одновременно
   │
   ├─→ worker: audiogen        (свой .venv, локальный порт, стартует лениво по первому запросу)
   ├─→ worker: stable-audio-open
   ├─→ worker: bark
   └─→ worker: ace-step
```

- **Воркер** — маленький HTTP-сервер (FastAPI/Flask) внутри `.venv` каждой модели:
  `/load`, `/generate`, `/status`, `/unload`. Держит модель в VRAM между запросами (не
  перезагружает веса на каждую генерацию — иначе каждый клик ждал бы 10-60 секунд впустую).
- При переключении на другую модель (или клике «Сгенерировать» на другой вкладке, если текущий
  воркер уже занимает VRAM) — оркестратор сначала останавливает предыдущий воркер (`/unload`,
  освобождает VRAM), потом лениво поднимает нужный. Пользователь видит статус
  «Загрузка модели…» с индикатором.
- Автовыгрузка по простою (например, 10 минут без запросов) — чтобы не держать VRAM занятой
  зря, если пользователь ушёл.
- Прогресс генерации — где API модели отдаёт колбэк по шагам (Stable Audio Open, ACE-Step) —
  показывать реальный %; где нет (Bark, AudioGen) — индикатор с прошедшим временем.

## 4. Общий UX

- Вкладки сверху: `AudioGen | Stable Audio Open | Bark | ACE-Step | Hunyuan-Foley ↗ | YuE ↗ | Галерея`
- На каждой модельной вкладке: основные поля видны сразу, доп. параметры — в
  свёрнутых блоках-аккордеонах, сгруппированных по смыслу (см. §5). Кнопка «Сгенерировать»,
  индикатор статуса/прогресса, плеер результата сразу под кнопкой.
- Тёмная/светлая тема — по системной, простым CSS (не критично, не блокирует приёмку).

## 5. Функционал по моделям

### AudioGen
*Источник параметров: `audiocraft.models.AudioGen.set_generation_params`*

- **Основное**: промпт (текст), длительность (сек, слайдер 1-30)
- **Доп. → «Сэмплирование»**: temperature, top_k, top_p, use_sampling (вкл/выкл)
- **Доп. → «Guidance»**: cfg_coef, two_step_cfg
- Seed: фиксируется через `torch.manual_seed` перед генерацией (в API модели нет отдельного
  параметра — реализуется на стороне воркера)
- Предупреждение в UI: веса `facebook/audiogen-medium` — CC-BY-NC, только некоммерческое
  использование результатов.

### Stable Audio Open
*Источник параметров: `diffusers.StableAudioPipeline.__call__`*

- **Основное**: промпт, длительность (audio_end_in_s, до ~47с)
- **Доп. → «Качество»**: num_inference_steps, guidance_scale, negative_prompt
- **Доп. → «Вариативность»**: seed, num_waveforms_per_prompt (сколько вариантов за раз)
- **Доп. → «Продолжение аудио»** (опционально, если делать audio2audio): загрузка
  референс-файла → `initial_audio_waveforms`

### Bark
*Источник параметров: `bark.generate_audio`*

- **Основное**: текст (с подсказкой в UI про спецтеги `[laughs]`, `[sighs]`, `[music]` и т.п.),
  выбор голоса из пресетов (выпадающий список — в комплекте 141 пресет, `en_speaker_0..9`,
  `de_speaker_0..9`, и др. языки + `announcer`)
- **Доп. → «Температура генерации»**: text_temp, waveform_temp
- **Доп. → «Производительность»**: переключатель `SUNO_USE_SMALL_MODELS` (быстрее/легче,
  ниже качество) — требует перезапуска воркера с моделью
- Seed: `torch.manual_seed` на стороне воркера

### ACE-Step
*Источник параметров: `acestep.pipeline_ace_step.ACEStepPipeline.__call__` (самый богатый API из всех четырёх)*

- **Основное**: промпт-стиль (жанр/теги), текст песни (lyrics, многострочное поле),
  длительность (audio_duration)
- **Доп. → «Диффузия»**: infer_step, guidance_scale, scheduler_type, cfg_type, omega_scale,
  guidance_interval, guidance_interval_decay, min_guidance_scale
- **Доп. → «Влияние текста/лирики»**: guidance_scale_text, guidance_scale_lyric,
  use_erg_tag/use_erg_lyric/use_erg_diffusion (переключатели)
- **Доп. → «Сид и вариативность»**: manual_seeds, retake_seeds, retake_variance, batch_size
- **Доп. → «Режимы»** (расширенная функциональность, отдельный раздел):
  - `audio2audio` — загрузка референс-трека + ref_audio_strength
  - `repaint` — перегенерация участка трека (repaint_start/repaint_end) поверх src_audio_path
  - `edit` — замена стиля/лирики существующего трека (edit_target_prompt/edit_target_lyrics,
    edit_n_min/edit_n_max/edit_n_avg)
  - LoRA: lora_name_or_path + lora_weight (в репозитории есть готовый `ZH_RAP_LORA`)

## 6. Галерея

- Список всех генераций (все модели вперемешку, с фильтром по модели): дата, модель, промпт
  (обрезанный), длительность, встроенный `<audio>` плеер.
- Клик по записи — разворачивает все параметры, с которыми она была сделана (JSON), кнопка
  «Повторить с этими параметрами» (переносит в форму соответствующей модели).
- Удаление записи — удаляет и файл, и запись из истории.
- Хранение: файлы в `app/data/outputs/<model>/<uuid>.wav`, метаданные — SQLite
  (`app/data/gallery.db`, через стандартный `sqlite3`, без ORM — объём небольшой).

## 7. Нефункциональные требования

- Только localhost, без авторизации (однопользовательская машина).
- Один запрос генерации в моменте (без очереди на MVP) — если генерация уже идёт, кнопка
  «Сгенерировать» на других вкладках неактивна с пояснением.
- Разумная обработка ошибок воркера (OOM, битые веса и т.п.) — показывать текст ошибки в UI,
  не роняя оркестратор.
- Windows-специфика уже учтена в самих моделях (см. `README.md` — абсолютные пути для
  ACE-Step и т.д.), приложение не должно её дублировать/переизобретать.

## 8. Вне рамок v1

- Очередь из нескольких генераций подряд (батчинг)
- Многопользовательский доступ / авторизация
- Кнопки «скачать/обновить модель» внутри приложения (это задача из README, не из этого ТЗ)
- Мобильная адаптация интерфейса
- Реальная интеграция Hunyuan-Foley/YuE (только внешние ссылки)

## 9. Критерии приёмки

Для каждой из 4 моделей:
- [ ] генерация через UI даёт реальный, проигрываемый файл, отражающий введённые параметры
      (например, смена длительности/seed видимо меняет результат)
- [ ] переключение на другую модель освобождает VRAM предыдущей (проверяется `nvidia-smi`
      до/после) и лениво поднимает новую
- [ ] все доп. параметры из §5 доступны и реально передаются в вызов модели
- [ ] Галерея показывает новую генерацию сразу после завершения, плеер работает, удаление работает
- [ ] вкладки Hunyuan-Foley и YuE открывают корректные внешние ссылки
